# 20 предложений по улучшению Babyshop

## Безопасность
1. **HTTPS-подпись Telegram initData**: сейчас telegram_id передаётся как есть от фронтенда — стоит на сервере проверять криптографическую подпись `initData` (Telegram даёт hash для этого), чтобы никто не мог подделать чужой Telegram ID через прямой запрос к API в обход Mini App.
2. **Rate limiting**: добавить ограничение частоты запросов (например, express-rate-limit) на `/api/login` и `/api/register`, чтобы защититься от перебора паролей.
3. **Ограничение размера загружаемых файлов** уже стоит (5 МБ), но стоит также проверять MIME-тип файла на сервере (сейчас multer это не делает), чтобы через "фото" нельзя было залить исполняемый файл.
4. **HTTPS-only cookies вместо localStorage** для токена пользователя — localStorage уязвим для XSS-атак; если в проект попадёт сторонний скрипт, он сможет украсть сессию.
5. **Ограничение попыток входа**: временная блокировка аккаунта после 5 неудачных попыток входа подряд.
6. **Настоящий ENCRYPTION_KEY**: сейчас в .env.example стоит заглушка — обязательно сгенерировать случайный 32-байтовый ключ и никогда не публиковать его.
7. **Резервное копирование базы данных**: настроить автоматический бэкап `babyshop.db` (например, ежедневно копировать в облако), чтобы не потерять все заказы при сбое сервера.

## UX / Интерфейс
8. **Push-уведомления в самом боте** о смене статуса заказа клиенту (не только owner/brother) — чтобы клиент не заходил проверять вручную.
9. **Поиск с подсказками (autocomplete)** в каталоге — по мере ввода показывать похожие товары.
10. **Избранное/wishlist** — чтобы постоянные клиенты быстро повторяли частые заказы.
11. **История цен** — если цена товара меняется, показывать клиенту "было/стало", это повышает доверие.
12. **Индикатор "товар закончился"** — сейчас `active` поле есть в базе, но нет визуального статуса "нет в наличии" отдельно от "скрыт".
13. **Кнопка "Повторить заказ"** в истории заказов — одним нажатием собрать в корзину те же товары.
14. **Групповая доставка** — если несколько аптек в одном районе заказали в один день, показывать это брату для оптимизации маршрута.

## Бизнес-логика
15. **Минимальная сумма заказа** — многие такие сервисы ограничивают заказ снизу, чтобы поездка была рентабельна.
16. **История изменений цен для админки** — сейчас при правке цены старое значение теряется; лог изменений цен полезен для анализа.
17. **Статистика для владельца**: экран с общей выручкой за период, топ товаров, топ клиентов — сейчас данные есть в базе, но нет сводки.
18. **SMS-дублирование уведомлений** (если Telegram недоступен) — критично для брата в дороге, если у него плохой интернет.
19. **Автоматическое напоминание клиенту**, если заказ висит в статусе "новый" больше суток без реакции администратора.
20. **Экспорт заказов в Excel** прямо из админ-панели за выбранный период — для бухгалтерии/отчётности, когда до неё дойдёт дело.
